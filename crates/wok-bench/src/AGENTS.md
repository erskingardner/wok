# wok-bench/src

Single binary: `main.rs`, plus `clients.rs` for `--scenario clients` (the only scenario that keeps abuse controls and AUTH on; it can run against a supplied relay TOML with `--relay-config`) and `author_kinds.rs` for `--scenario author_kinds` (a planner sweep on a large, kept dataset, optionally against a second wok binary with `--wok-baseline`). `tag_kinds.rs` is `--scenario tag_kinds` (`#p`/`#e` + `kinds` fetches on its own kept dataset; it reads the dataset's Tag index in process, before any relay starts, to count the events a Tag-index plan reads). `transport.rs` is `--scenario ws_transport` (per-connection memory, bursts, fan-out, churn and codec levels, with and without permessage-deflate). `social.rs` writes `--event-mix social` corpora: events are built in order on one thread, so ids exist before signing, then signed in parallel batches; reposts embed notes from earlier batches only. `corpus.rs` streams a corpus once for the read scenarios (`ws_query_latency`, `deep_history_pagination`, `mixed_read_write`), which with the in-process `codec_cpu` are the only ones a social corpus runs, parsing on every core and keeping each event compact (id, author, kind, `created_at`, a digest of the event, interned single-letter tags) so #226's 50M tier fits a load host: it works out what a relay keeps (replacement, NIP-09 deletion, one copy per id, no ephemerals), plans the queries, and checks replies, accepting any of a second's events where a `limit` cuts through it.

`catchup.rs` is `--scenario nip77_catchup`: it plans filters and the client's held share from the corpus (what a relay keeps of it), runs the NEG-MSG rounds and the id fetches with `wok_negentropy` as the client, and checks the relay's have/need ids and returned events against the plan. Kinds Wok serves only after AUTH may be withheld, but only in full.

`live.rs` holds `--scenario monitor_index` and `--scenario live_subscriptions`: many live subscriptions with distinct author lists, churn and a reconnect storm. `monitor_index` runs `wok_query::ActiveMonitors` in process, so it measures the index compiled into the bench binary, not `--wok`.

Principles at the top of the file: disposable DBs, identical corpus for both relays, warm-up, correctness gates. CLI flags select `--profile smoke|full`, `--scenario`, `--strfry`, `--wok`, `--out`, seed, mix, and scale knobs.

Output is JSONL plus a markdown summary under `--out` (default `bench-results`). Reproduce from the repo README; interpret numbers using `docs/benchmarks.md` rather than a single local run.
